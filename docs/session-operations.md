# 会话操作契约（0.10.11 冻结）

这份文档记录 **0.10.11 这一稿的会话操作方式**。后续修改除非用户明确要求，否则不得改变以下行为。

## 1. 新建会话卡

- 「添加卡片 → 会话」创建的是**空会话卡**：`contentFor('session')` 返回 `{ kind: 'session', sessionId: '' }`。
- 空卡先显示工作区 → 会话树（`SessionTree`），由用户点选一场会话；不预选、不猜。
- 从宿主左侧栏拖一条会话行到画布，是**用户显式指定**：卡片带着那条会话打开（`DRAGGED = { kind: 'session', value }` → `addContent`）。这不算自动吸附。

## 2. 换会话

- 会话卡的标题本身就是下拉框（`TitlePicker`），按工作区分组，列出会话与归档开关；换会话只通过这个下拉或空卡树。
- **没有**链条按钮、没有「断开数据源」菜单项、没有 `chainOf` / `toggleChain` / `ownerOf` 的旧路径。
- **不按几何位置**找会话：没有 `neighborOf` / 左上方 / 上次会话 / 第一个会话的兜底。
- `boundSessionOf(leaf)` 只看 `leaf.sessionId`；会话卡不会从邻居继承。

## 3. 会话相关卡片

- `usage`（用量）、`context`（上下文占用）、`region`（片段）在卡头显示「选会话」下拉，写入 `leaf.bindId`。
- `ctx` 卡只有 **步骤明细 / 上下文事件 / 文件活动 / 命令执行** 这四种读单场会话，显示下拉；看板 / 会话表 / 每日用量 / 技能榜是全局视图，不显示下拉。
- `ocr` 不绑会话（本机识别），不显示下拉。
- 统一取会话顺序：`leaf.bindId` → `leaf.sessionId` → 空。`boundFor()` 是唯一入口。

## 4. 一份会话只跑一份客户端

- `sessionOwner(sid)` 找出当前持有该会话的会话卡；重复的卡显示「这个会话已经在另一个窗口里显示 / 改在这里显示」，不会静默开第二份。
- 活池 `live` 有上限（`liveCap()`，由代理端口数决定）；冷卡显示「这个会话在排队」，点「换到这里」或「全部挂起」。
- 同一张卡的 iframe 在切换会话时重挂，但不会因为布局/拖拽自动换会话。

## 5. 拖拽与复制

- 拖动会话卡的标题到别的卡片边缘：整叶克隆，`sessionId` 跟着走，落点只做拆分/插入，不做中心替换（`noCenter`）。
- 拖到空格子里：空格子换成这张卡的内容。
- 复制一份/拖到画布：保留 `sessionId`；不自动改绑。

## 6. 不要改的地方

以下都不是“体验优化”可以顺手改掉的：

1. 空会话卡默认不选任何会话。
2. 卡头下拉是唯一换会话入口。
3. 不增加任何基于位置、焦点、最近使用、邻居的自动绑定。
4. 不恢复链条/吸附 UI。
5. 一份会话只允许一个活客户端，重复卡保持排队卡。
6. 全局 ctx 卡不再加会话下拉；OCR 不加。
7. 从宿主拖会话行进来仍然直接绑那一场（显式拖拽例外）。

## 7. 回归检查（手工）

- 新建会话卡 → 应显示会话树，不自动加载。
- 选一场 → 加载；标题下拉换另一场 → iframe 与标题一起换。
- 同一场再开一张 → 第二张显示「改在这里显示」。
- 用量/上下文/片段 → 卡头有「选会话」；OCR 没有。
- 看板/会话表/每日/技能榜 → 卡头没有「选会话」；步骤/事件/文件活动/命令执行有。
- 把会话卡拖到另一张卡边缘 → 仍是同一场会话，不跳。
- 刷新 → 选择保持。
