窄屏那次 `divider-min` 给出 880×768 / 880×299：新窗口按自适应方向改成上下劈分，最小高度 299px，不再是「一条缝」。

八项各自的含义：

- `zoom-in`：点一次「放大」，iframe 的 `style.zoom` 从 1 到 1.12（并用 `data-zoom` 记住）。改用 CSS `zoom` 之前，`transform` 只会把内容画小、右边留白。
- `divider-min`：把分隔条拖过界，两侧仍不小于最小尺寸（190px 或按可用空间的夹取值）。
- `center-drop`：往窗口正中丢一个网址，叶子数不变 —— 是替换内容，不是新开窗口。
- `persist`：树里几个窗口 = `localStorage` 里几个。
- `pick-to-window`：在侧栏取点后叶子数 2 → 3，且新叶子是 `region`。
- `panel-window`：面板窗是一个指向代理的 iframe（`?fpEmbed=panel:files`）。
- `api-window`：插件接口窗从宿主读回 6 个已装插件。
- `frost`：`body.fp-dragging` 时窗口 `::after` 的 `content` 从 `none` 变成 `""`（雾面层），松手后恢复。

## 本轮修掉的两个真 bug

1. **取点模式下画布整个按不动**：取点层的 click 处理器对「没找到合适目标」的点击也做了 `preventDefault + stopPropagation + 关闭取点`，于是点窗头按钮既没反应、还会顺手退出取点。现在只要点击落在 `.fp-canvas` 里就直接放行（不取点、不吞事件、不关取点）。
2. **`?fpReset=1` 把树置成 `null`**：打开是纯空画布、窗口都没有（自检「没动静」也是这个原因）。现在重置成一个带选择器的空窗口。
